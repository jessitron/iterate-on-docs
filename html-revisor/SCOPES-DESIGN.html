Decided: editing as markdown

The design decisions for scopes and markdown editing. Each links to the cases below that show it.

question answer see
Editing notation Markdown. A1
What can you pick to edit or direct? Any block: a section, a list, one item, a table, one cell, an svg text label. Each edits its whole content as markdown. A1, C1, C6, D6
What can't you pick? An element an agent marks data-no-revise, and all inside it. No marks, no box, and clicks stay the page's. The rule is in the client: the element still gets an ID, and the tables below show its rows as not pickable. D7, D9, D10
Can editing a parent change a data-no-revise element? Yes. The parent's markdown holds it, so editing the parent can change it. The mark limits what you pick, not what an edit reaches. D9, D10
How big a scope edits as markdown? Under 4 KB of HTML, not counting element IDs and directives. A bigger one, such as a page's body or a wrapper around a whole page, takes directives and has no Content field. test/scopes.test.mjs, "Size"
Inline elements: hover and directives? Per element. a and img: yes. strong: no, it belongs to its block. span: yes, edited as its content, its tag kept; not inside a pre, where spans are highlighting, and not one that fills its parent, which it would hide. B2, D2, E1, E2
Headings # inside a bigger scope; picked alone, only the text. A3
Line breaks and &nbsp; A <br> is a newline. U+00A0 shows as the character. A4, A5
Lists Markdown - lines, nested lists indented. Add and delete items by editing. A list holding paragraphs or tables: pick the inner blocks too. C1, C2, C3
Code blocks A fenced block: backticks for <pre><code>, tildes for a bare <pre>. A pre holding markup (highlighting) is HTML, so its spans survive. C11, D3
Text beside blocks Paragraphs in the enclosing scope's markdown: text, list, text edits as one. Text saved unchanged stays bare. Where a block broke a p, the formatter puts the text after it in a p and drops the empty one the stray </p> left. C9, C10, F3
Tables A table with a header row of plain cells is a markdown table; otherwise HTML. Each cell is a scope too. C6, D4
What markdown can't say Stays as inline HTML (kbd, span class). Inside a bigger scope, a block with attributes is HTML too, inner markup and all, since markdown isn't read inside an HTML block. B1, B2, B3, C4, C8
Images ![alt](src); saving takes the other attributes from the original. D2
Links [text](href "title"), whatever other attributes the link has. Saving pairs each link with an original: the same href and text, then the same href, then the same text, each a pass over all the links. Markdown wins for href, title, and text; the original gives back the rest, class and target among them. A link or image written as HTML keeps what it says. B2, test/scopes.test.mjs
What isn't text A stand-in: ⟦svg⟧, ⟦script⟧, restored from the prior HTML (see identity). A literal ⟦ is \⟦. Hidden elements get stand-ins too, so a save keeps them, and inside HTML the markdown writes, a style's blank lines can't end the HTML block. There, a literal ⟦ is &#x27E6;, and a stand-in takes the next of its kind. D1, D5, D7
Writing markdown Rules make it readable; each block and run of phrasing is checked against the parser, and written as HTML where it wouldn't come back the same. The round-trip holds by construction. A2, B4
Unlikely shapes in HTML ⇄ markdown (empty paragraphs, dl, stat tiles) May be ugly. Spend effort on the shapes agents write. C4, E1, F1
Where markdown converts On the server, where to-markdown.mjs, from-markdown.mjs, and linkedom run; the client stays small. No live preview.
Parser and writer markdown-it parses. The writer is our own, in to-markdown.mjs, because it carries the rules in this table; a general HTML-to-markdown library would need each one overridden.

Decided: element identity

Directives, the open box, and the conflict check find elements by ID. A markdown save rebuilds the HTML of its scope, so a save has to say which new element is which old one.

question answer see
Where does an element's ID live? In the file, as data-hrv. An edit that adds or removes elements shifts a tree path or an index; an ID in the file stays put.
What kind of ID? A counter, for short IDs, with its high-water mark in <html data-hrv-next>. Never reused; an ID lasts as long as its element. Copies of one ID all get fresh ones.
Who assigns them? The formatter, on every GET and first thing on every PUT. Agents leave both attributes alone; an element they add gets its ID on the next load.
Saves and conflicts One change per save, checked against the base of its own element. A change elsewhere in the file brings a notice and the save goes through. A conflict means turn-taking broke: the save fails with an error that suggests a reload.
IDs after a markdown save Reconciled against the prior HTML. Siblings pair the way a diff does: the ones that came back the same, then, between those, the most alike with the same tag. An edited element keeps its ID, a moved one keeps its own, and a new one gets a fresh ID from the formatter. A pair's children pair the same way. C1
Stand-ins after a markdown save Each token takes the original of its kind whose enclosing elements, tag and text, are most like its own, nearest first; a tie goes to the next in order. A block you removed takes its stand-ins with it, and a block you moved keeps its own. The token carries no ID. D8
Directives across a markdown save Each rides to its element's partner, in order. The markdown doesn't show them.
A directive whose element a markdown save deleted? Goes with it.
IDs on a page leaving the tool A cleanup script strips them and the directives, the formatter in reverse, and the commits get squashed.

What is a scope?

A scope is any block you can pick: you leave a directive on it, or edit its whole content as markdown. Each case has the same four parts: its name, the question it asks in grey, the example HTML in a dashed box, and a table of the scopes the example would make. Disagree with a row? Leave a directive on it.

Under each example: its HTML (click to open), then a row for each element you could pick, nested inside the element that holds it, and one marked not pickable for each element inside data-no-revise. The last column is the markdown you would edit if you picked that element. ⟦svg⟧ marks something that isn't text riding inside the markdown.
