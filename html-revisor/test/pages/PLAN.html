The formatter stands alone

formatter.mjs holds parse, skeleton, layout, serialize, and an empty rule list; server.mjs imports it. node formatter.mjs <file>... rewrites in place, silent on success; exit 1 for a problem, 2 for no files. It's in the contract: iterate-on-a-document and make-a-project-overview run it. Deployed at 3634b9c.

2

Decide what makes a scope

Started as "what makes a prose chunk". It became: you pick any block, from a section down to a list item or a cell, and edit its whole content as markdown. The decisions are in the table below. The tool is scopes.mjs; --annotate shows each case in try-me.html as its HTML, scopes, and markdown. p5pm

3

Element ID rewrite

IDs written into the file, so an edit that adds or removes elements shifts no one's ID. a17m

  • data-hrv="7" from a counter; the high-water mark is <html data-hrv-next="…">. Never reused. Duplicates retire the ID: every copy gets a fresh one.
  • The formatter assigns IDs on every GET and first thing on every PUT. Existing IDs never change.
  • A save carries one change and the base it started from: {id, base, directive}, {id, base, text} for a text element, and later {id, base, markdown} for a scope. No file-wide version, no 409. A conflict is a 412.
  • A conflict means turn-taking broke: the save shows an error and suggests a reload. cqsh
  • The tab hears of outside changes on save, as a notice, never a block. 0so7 Live notice is in the polish lane.
  • Contract: agents leave data-hrv and data-hrv-next alone. In the README and in iterate-on-docs.
4

Scopes

The rule from stage 2, in code, up to markdown. Every block element, link, and image takes directives. Scopes nest, so one edit can change the elements inside another scope. Offering each scope's markdown in the box is stage 5.

  • Inline elements, per element: a and img take hover and directives; strong doesn't. Only elements with an ID take them.
5

Round-trip, in code

scopes.mjs turns any scope into markdown and markdown back into HTML. Opening a scope and saving it unchanged gives back the same HTML, IDs and directives aside. Unlikely shapes come out ugly, and still round-trip. Nothing calls it yet: stages 6 to 8 put it to use.

  • Done: the client script lives in client.js, so client work no longer collides with server work. tl5y
  • Parser: markdown-it, vendored like linkedom. CommonMark with GFM tables; raw HTML passes through; a newline is <br> (A4). Writer: our own, in scopes.mjs: it carries the Decided rules, and turndown would need each one overridden. 6u05
  • Done: the inverse, scopeFromMarkdown, and the property test, test/roundtrip.test.mjs: every scope in this repo's pages, and seeded pages full of * _ ` [ # &, round-trip, IDs and directives aside. The writer checks each block and run of phrasing against markdown-it and writes HTML where markdown wouldn't read back the same. s8s3
  • Done: canonical forms. The formatter rewrites b→strong, i→em, puts table rows in thead/tbody, and drops whitespace beside <br>, so what markdown writes back is what the file holds. Formatting, not a validation rule: no agent hears of it. w3yn
  • Done: stand-ins. ⟦svg⟧ and ⟦script⟧ come back as the original element; an image keeps its other attributes. 25ov
6

Reconcile: IDs survive a save

Saving a list's markdown builds new HTML for everything inside the list. Those elements have no data-hrv, so the formatter gives each a new ID, edited or not. Directives, the open box, and the 412 check all find elements by ID. Reconcile matches the new elements to the prior ones: a match keeps its ID and the attributes markdown can't say (img width and height). An element with no match is new and gets a new ID. eq9q

  • Done: scopeFromMarkdown reconciles. Siblings pair the way a diff does: equal ones first, then, between those, the most alike with the same tag. An edited element keeps its ID, so its directives can stay (Jess, 2026-10-12); a moved one keeps its own; a new one gets none.
  • Done: the property, in test/roundtrip.test.mjs. Saving unchanged keeps every ID. Edit any scope, by a word, a new element, a removal, a swap, or a word and a new element beside it: each ID lands on the element with the same tag and text.
  • Found by the swap: two images of one picture traded sizes. An image now takes back the attributes of the prior image most like it. Found by a removal: deleting an inline icon handed its place to a diagram further down, which came back inside a paragraph. A stand-in alone in its paragraph now takes the next one that stood between blocks.

The contract

What iterate-on-docs relies on; the README's “Contract” table is the source. A change here travels with a matching edit there.

server path ../../html-revisor/server.mjs

Decided

question answer
Format or prose first? Format, for its validation steps.
Validation rules None until needed.
Element IDs in the file? Yes, so edits can't shift them. Changed 2026-10-12, with scopes. A tree path or index shifts the same way; only an ID in the file gives an element an identity.
What kind of ID? A counter, for short IDs, with its high-water mark in the file. Never reused. An ID is stable for the life of its element.
Saves and conflicts One change per save, checked against its own scope. No file-wide version. A conflict is an edge case: error, suggest reload. A changed page is a notice, not a block.
IDs after a markdown edit of a wider scope Unchanged elements keep them, reconciled against the prior HTML. Intent; built with markdown editing.
IDs on a page leaving the tool A cleanup script strips them, roughly the formatter in reverse. Pairs with squashing the commits. 41o3
Editing notation Markdown, not contenteditable. Research in commit 8683442.
Formatter CLI in the contract? Yes. iterate-on-docs changes with it.
What can you pick to edit or direct? Any block: a section, a list, one item, a table, one cell, an svg text label. Each edits its whole content as markdown. Replaces "one chunk, nothing inside it", 2026-10-12.
Lists Markdown - lines, nested lists indented. Add and delete items by editing. A list holding paragraphs or tables: pick the inner blocks too.
Code blocks A fenced block: backticks for <pre><code>, tildes for a bare <pre>. A pre holding markup (highlighting) is HTML, so its spans survive (Jess, 2026-10-12).
Text beside blocks Paragraphs in the enclosing scope's markdown: text, list, text edits as one. Text saved unchanged stays bare.
Tables A table with a header row of plain cells is a markdown table; otherwise HTML. Each cell is a scope too.
What markdown can't say Stays as inline HTML (kbd, span class, a target). Inside a bigger scope, a block with attributes is HTML too, inner markup and all, since markdown isn't read inside an HTML block. f6im
Headings # inside a bigger scope; picked alone, only the text.
Line breaks and &nbsp; A <br> is a newline, not a backslash. U+00A0 shows as the character.
Images ![alt](src); saving takes the other attributes from the original.
Unlikely shapes in HTML ⇄ markdown (empty paragraphs, dl, stat tiles) May be ugly. Spend effort on the shapes agents write.
Inline elements: hover and directives? Per element. a and img: yes. strong: no, it belongs to its block.
Writing markdown Rules make it readable; each block and run of phrasing is checked against the parser, and written as HTML where it wouldn't come back the same. The round-trip holds by construction. 8hlj
What isn't text A stand-in: ⟦svg⟧, ⟦script⟧, restored in order from the prior HTML. A literal ⟦ is \⟦. Hidden elements used to be left out of the markdown, so saving would have dropped them (Jess, 2026-10-12).
Where markdown converts On the server, where scopes.mjs and linkedom run; the client stays small. No live preview for now (Jess, 2026-10-12).
The word scope, not chunk.
Shipping ./deploy here copies into iterate-on-docs; ./release there publishes.
SVG commenting Stays as is.
