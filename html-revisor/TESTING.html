How we test

149 tests, all passing, in 18 seconds. They took 57 until scopes over 4 KB stopped editing as markdown. One test file still holds nearly all of the time.

The suite

npm test is node --test. It runs each file under test/ in its own process, several at once, so the suite takes as long as its slowest file. No dependencies: deploy runs these tests inside iterate-on-docs, where npm install can't run.

Every ship runs the suite three times: once by hand, once in ./deploy, once in iterate-on-docs' release. Deploy and release both test the copied files in iterate-on-docs/html-revisor/, so a file deploy missed fails there. Deploy tests the copy before it commits it; release tests it again. Release's run catches a hand edit to the copy, or a release with no deploy in front of it.

After limiting scope to 4 KB

Jess tried editing scopes on real pages. A long list in DESIGN.html was one she wanted to edit as markdown: 3 KB of HTML, 2.2 KB of markdown. The limit went to 4 KB so that list stays editable.

A scope of 4 KB of HTML or more, not counting element IDs and directives, has no Content field. It takes directives. The round-trip tests skip it, since it has no markdown to test.

Recommendations

  1. Split roundtrip.test.mjs into files. Property tests on generated pages in one file, tests on specific files in another, with shared generators and checks in test/roundtrip-lib.mjs. Split further if one file still runs long. node --test runs files side by side, so the suite waits on the longest. Same tests, same seeds. The round-trip file is 17.7 s and its longest test is 2.0 s, so a split could bring the suite to a few seconds. Yak: "Split roundtrip.test.mjs into files so node --test runs them side by side".
  2. Run the suite once per ship. Deploy and release test the same commit back to back. Release could skip its run when the vendored commit hasn't changed since the deploy that tested it. That change lives in iterate-on-docs.

Not recommended: dropping or shrinking the mintlify page. It's the one page in the suite shaped like the wider web, and it caught three bugs in its first day.

What the round-trip file checks

Two properties. Each runs over every scope under 4 KB of every page it's given: no examples, no picking.

Round-trip

Scope → markdown → scope gives back the same HTML, IDs and directives included. Opening a box and saving it unchanged leaves the file unchanged.

Reconcile

Edit a scope (change a word, insert, remove, swap, or word and insert), save its markdown over the old one. Each element keeps its ID and its directive.

Tidy markdown

Pages in the shapes agents write most come out as markdown, HTML only for section and card tags.

The same checks run two ways: as property tests on generated pages, and on specific files. Each test loops over its pages one after another.

Why that page cost so much

Both properties do work in proportion to the size of each scope, and scopes nest. A paragraph is counted once on its own and once more inside every scope around it. Markdown takes about 0.9 µs per byte of scope, on every page.
