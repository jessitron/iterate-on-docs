How we test

What each kind of test is for, how to keep the suite fast, and dated records to compare against.

The suite

npm test is node --test. It runs each file under test/ in its own process, several at once. No dependencies: deploy runs these tests inside iterate-on-docs, where npm install can't run. node --test runs every .mjs under test/, so each -lib file counts as one test.

Every ship runs the suite three times: once by hand, once in ./deploy, once in iterate-on-docs' release. Deploy and release both test the copied files in iterate-on-docs/html-revisor/, so a file deploy missed fails there. Deploy tests the copy before it commits it; release tests it again. Release's run catches a hand edit to the copy, or a release with no deploy in front of it.

What the round-trip files check

Each property runs over every scope under 4 KB of every page it's given: no examples, no picking. A scope of 4 KB or more has no Content field, so it has no markdown to test.

Round-trip

Scope → markdown → scope gives back the same HTML, IDs and directives included. Opening a box and saving it unchanged leaves the file unchanged.

Reconcile

Edit a scope (change a word, insert, remove, swap, or word and insert), save its markdown over the old one. Each element keeps its ID and its directive.

Tidy markdown

Pages in the shapes agents write most come out as markdown, HTML only for section and card tags.

The same checks run on three sets of pages. The generators and checks they share are in test/roundtrip-lib.mjs.

Pages Why
Generated, 150 seeds, tidy and wild Shapes and characters markdown reads as syntax, more than any real page holds
test/pages/: OVERVIEW, DESIGN, SCOPES-DESIGN Frozen copies of this repo's pages: the shapes Jess's agents write
test/pages/mintlify-animal-fables.html A published docs page, anonymized: divs nested deep, inline styles, a toast holding a <style>. The test case for save performance.

Keeping it fast

  1. Measure before cutting. Files run side by side, so the suite takes as long as its slowest file. Time each file alone, and cut the longest; a cut to any other file leaves the suite where it was. A file that computes runs a quarter longer side by side than it does alone, and a file that waits doesn't.
  2. Split a slow file along a line of meaning. Tests inside one file run one after another, and files run at once. A long file of independent work becomes two files, split by what they check.
  3. Run the server in the test's process. Start it from createServer. Spawning a process costs about 100 ms a test.
  4. Close the server's sockets. Call server.closeAllConnections() beside server.close(). A keep-alive socket can hold the close for 3 s. Time a test's phases to see whether it does.
  5. Run the tab on a fast clock, and wait on events. The tab's timers run at a tenth of their length, and a tab waits for the server's connect event in place of a sleep.
  6. Keep waits for nothing short, and few. A test that hears no notice has to wait a fixed length. Make it longer than the slowest real notice under load, and share one wait between checks where you can. Then break the server on purpose, to see the test fail.
  7. Keep big scopes out of the round-trip. Work grows with scope size and scopes nest, so a few big scopes take most of the time, and the bugs don't need them. That's the 4 KB limit. Keep the mintlify page: it's the one page shaped like the wider web, and it caught three bugs in its first day.

2026-10-15: why the mintlify page cost so much

Round-trip and reconcile do work in proportion to the size of each scope, and scopes nest. A paragraph is counted once on its own and once more inside every scope around it. Mintlify's body holds more than a dozen wrapper divs, each one a scope holding nearly the whole page.

Page File Scopes Deepest All scopes, added up × file

OVERVIEW 42 KB 319 9 197 KB 4.7
SCOPES-DESIGN 79 KB 925 10 440 KB 5.6
mintlify-animal-fables 321 KB 717 19 4,020 KB 12.5

15 of mintlify's 717 scopes were 50 KB or more, 2% of them, and they took 85% of its markdown time. None of the three bugs this page caught needed a big scope: the smallest failing scope was a 1 KB <li>.
